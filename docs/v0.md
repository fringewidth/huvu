# What is left for v0

v0 here means: the family uses huvu every day on Android phones and on the web. It runs against a live Hermes, the doorbell reaches it, and approvals and notifications reach phones while the app is closed. Fire TV, iOS and live feeds are under "Decide", because each one is a large piece of work and could wait for v1.

Written on 2026-10-06. Other lists go into more detail: `frontend-changes.md`, the open questions in `backend-architecture.md`, and the known gaps in `CLAUDE.md`.

## Decide first

1. **Where the backend runs, and how phones reach it from outside the house.** The phone app needs HTTPS. Capacitor serves the Android app from `https://localhost`, and the WebView blocks calls from it to a plain `http://` backend. One option is a machine at home behind a tunnel (Tailscale, or a Cloudflare Tunnel). Keeping the backend at home also keeps the Fire TV's ADB on the same network.
1. **Voice on the phone.** The Android WebView has no Web Speech API, so speech to text on the phone is the mock today. huvu's voice is one test clip. For v0, either put real speech to text and text to speech behind the backend, or hide voice mode on the phone until they exist.
1. **Fire TV in v0 or not.** Still to build: the Alexa skill, a decision on how its ask reaches the backend, the ADB launch, the `LEANBACK_LAUNCHER` entry, the TV's visual pass, and a test on the hardware.
1. **iOS in v0 or not.** Nobody has tried an iOS build. It needs Xcode. Native push needs a paid Apple developer account for the APNs key. Without that account, a build installed from Xcode expires after 7 days.
1. **Live feeds in v0 or not.** No WHEP endpoint exists. The backend's WebRTC stack is not chosen (aiortc is the obvious pick and is untried). The other way is a media server such as mediamtx that relays a camera's RTSP.
1. **The Home Assistant driver in v0 or not.** The driver is built (2026-10-06) and tested against a fake HA. What's left is the HA side, see the setup list.

## Set up (you)

1. **Firebase project.** Add the Android app `com.huvu.app` and put its `google-services.json` in `frontend/android/app/`. Make a service account key with the Firebase Cloud Messaging API on, and set `HUVU_FCM_CREDENTIALS` to its path. If iOS is in v0, you also need `GoogleService-Info.plist` and the APNs key uploaded to Firebase.
1. **Hermes.** Turn on its API server. Run `./setup.sh` once for the default profile, which the shared devices use. Then run `./setup.sh <username> <password> [name]` for each family member, which adds them as a user and makes their Hermes profile.
1. **Install the huvu Hermes plugin** (`hermes-plugin/huvu/`) in the running Hermes.
1. **Home Assistant**, if it is in v0: huvu's own HA user and token, the scripts, labels, exposure and power plugs. Agents can do this from `home-assistant.md`, which ends with an inventory to fill in.
1. **Tuya credentials** for the driver, kept outside the repo (for example `~/.tuya.env`, as in `backend/huvu.toml.example`).
1. **Hosting**, once the first decision is made: the backend as a service that restarts on its own, its `data/` directory backed up (SQLite holds the users, devices, triggers and event log), HTTPS, and `public_url` in `huvu.toml` set to the public address.
1. **Android release signing key.** A debug APK is fine to sideload for v0. If later APKs must install over earlier ones, keep one signing key from the start.

## Build

1. **The backend URL from the build.** `BACKEND` is hard-coded as `http://localhost:3001` in `frontend/src/net/http.ts`. Read it from a `VITE_` variable in each `.env.<target>`, the same way `VITE_TARGET` works.
1. **Tuya driver** (`backend/src/huvu_drivers/`): the Pulsar consumer, then the album fetch and decryption, so that a doorbell press reaches huvu as an event with an image part. The findings are in `front-door-lock.md`.
1. **Speech**, if the voice decision says so: speech to text and text to speech behind the backend, and `voice/transcriber.ts` and `voice/speaker.ts` moved over to them.
1. **The dream prompt**: the Hermes cron job that queries the history tables with `data_sql` and learns preferences (see `backend-architecture.md`, What Hermes owns).
1. **A deploy for the web app**: `npm run build:web`, served over HTTPS.

## Test for the first time

1. **The first turn through a live Hermes.** The backend has only run against a scripted Hermes. Check per-user profiles, the plugin's hooks, the MCP tools, and the prompt cache (a `conversation.turn` event carries `usage`).
1. **The doorbell, end to end**: press it, then ask huvu who rang.
1. **The first APK build.** `./gradlew assembleDebug` in `frontend/android`, with `JAVA_HOME` set to Android Studio's bundled JDK. The first try timed out while it downloaded Gradle.
1. **On the phone**: login, secure storage, the keyboard resizing the WebView, the hardware back button, the push stream across background and foreground, native push with the app closed, a tap on a notification, approvals and "is it you?".
1. **Native push with a real FCM message.** So far it has only been tested against a fake.

## After v0

1. Wake word (Android only), background location, home-screen widgets and the `?mode=voice` deep link.
1. Taps that wait: the message for an action tap that comes back `pending_approval` or `already_pending`. Nothing in the app taps an action yet.
1. Linking each person's own accounts (calendars and the like).
1. Finer roles than member and guest.
